# ADR-010：已删除内容的错误码沿用 `QA-1008`，不采用 `QA-1020`

**状态**：已接受 ｜ **驱动特征**：实现与文档一致、可追溯、最小改动 ｜ **决策日期**：2026-11-19

## 背景

Sprint 1 评审时提出一个悬而未决的问题：对**已软删除**的问题/回答做回答、编辑、采纳、投票、评论时，
实现返回 `422 QA-1008`，而《实验指导书》3.7 节的建议表里对应的场景写的是 `QA-1020`，Sprint 1 回顾
中也据此记了一条“需团队确认”的待办，但一直没有结论。

先把事实查清楚（最初我以为是“起始代码给定”，查过之后发现不是，这里按查证结果写）：

| 事实 | 依据 |
| :-- | :-- |
| 起始代码的 `docs/错误码.md` 共 **6 个** `QA-` 码，其中 1xxx 业务规则段只有 4 个（`QA-1001`、`QA-1002`、`QA-1005`、`QA-1015`），另有冲突段的 `QA-2002`、权限段的 `QA-3001` | `git show a0cacc5:docs/错误码.md` |
| `QA-1008` 是团队在 `468668c`（2026-10-22，PR #1 实现领域层时）按文件里“1xxx 业务规则 / 2xxx 冲突 / 3xxx 权限”的分段约定**自行编号并写回文档**的 | `git show 468668c -- docs/错误码.md` |
| 指导书 3.7 允许“未给定的场景按下表补充”，并要求补充后写回 `docs/错误码.md`；写入之后，“已给定的错误码必须严格使用” | 指导书 3.7 |
| `QA-1020` 在 3.7 表中来源列标注为“**建议**”，与 `QA-1008` 同属“未给定场景的补充建议”，没有优先级 | 指导书 3.7 |
| 该码已落地：主代码 **7 处抛出**（`Question` 3 / `Answer` 1 / `VoteService` 2 / `CommentService` 1）+ `CommentServiceTest` 1 处断言 | `grep -rn '"QA-1008"' backend/` |

结论：这不是“照抄起始代码”，也不是“违反指导书自创码”，而是**团队按 3.7 的分段约定自行编号、写回文档、并已形成实现与断言**。
3.7 真正约束的是“文档与实现一致、编号服从分段约定”，这一条我们已经满足；缺的只是把这次决策写下来。

## 决策

1. **保留 `QA-1008`** 作为“对已软删除内容执行写操作”的错误码，HTTP 状态 `422`，不做重编号。
2. 在 `docs/错误码.md` 中补齐两处：① 与指导书 3.7 的**映射表**（建议码 → 本团队取值）；
   ② `QA-4001` ~ `QA-4004` 的 **4xxx 明细**（此前只有一句 `NotFoundException`，映射表引用的码在文档里查不到）。
3. 按**读 / 写两条路径**区分语义，不再混用：
   - **写操作**（回答、编辑、采纳、投票、评论）命中已软删除内容 → `422` + `QA-1008`（BusinessRule）。
     写路径用 `findById` 能取到实体、能判断 `deleted_at`，所以给得出“内容存在但已删除”的精确提示；
   - **读操作**（详情、列表）命中已软删除内容 → 按不存在处理 → `404` + `QA-4001/4002`（NotFound）。
     读模型 `JdbcQaReadModel` 的 SQL 自带 `WHERE deleted_at IS NULL`（见第 81 行），已删除内容查不出来，
     `QuestionQueryService.detail` 对空结果抛 `QA-4001`；这与 ADR-006「已删除内容不出现在详情」一致。
4. 指导书 3.7 的方法表把 `loadQuestion` / `loadAnswer` 对已软删除统一写成抛 `404`。本团队只在**读路径**照此执行，
   写路径没有照做：写入场景若也返回 404，前端就无法区分“链接失效”与“作者已删除该内容”，
   而这正是 `QA-1008` 的存在意义。两套码并存不是矛盾，是两条路径各自的实现约束。
5. **新增错误码的流程**：先在 `docs/错误码.md` 里按分段约定编号并写清场景与抛出点，再实现。
   反过来（先写代码后补文档）就是这次出现“文档里查不到 `QA-1008` 出处”的原因。

## 后果

- 正面：零代码改动、零测试改动（`CommentServiceTest` 那 1 处断言原样保留），不触碰学术诚信红线（9.3）；
  语义边界被写清楚：**写路径 422 `QA-1008`（已删除）、读路径 404 `QA-4001`（不存在）**，
  前端按 `code` 就能分别提示“内容已被作者删除”和“链接失效”，不必只看 HTTP 状态码。
- 负面：与指导书 3.7 建议表的**字面**不一致，评审时可能被问；因此本 ADR 必须在评审会上主动出示。
- 约束：后续任何人不得为了“对齐指导书”而批量改错误码——那会连带修改既有断言，属于 9.3 红线。

## 已知不一致（不在本 ADR 范围）

`BountyService:62` 在 Reputation 上下文里抛的是 `QA-4001`（Q&A 的码），与“前缀 = 上下文”的分段约定不符。
改码要连带改动悬赏相关测试，建议单独开 PR 处理，本文档只做记录。

## 被否决的替代方案

- **全量改为 `QA-1020`**：需要改 7 处实现 + 1 处测试断言，违反“不修改已有断言”的约束，
  收益仅是字面与建议表一致。
- **改为返回 `404 NotFound`**：会把“已删除”与“不存在”合并，写场景下前端无法区分“链接失效”与“内容被删”，
  且 `404` 无法携带业务语义；指导书 3.7 把 `QA-1020` 归为 `BusinessRule` 也支持 422。
- **两个码都返回**（先 1020 再 1008）：语义重复，前端需处理两种分支，纯增复杂度。
