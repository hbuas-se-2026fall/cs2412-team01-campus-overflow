# ADR-010：已删除内容的错误码沿用 `QA-1008`，不采用 `QA-1020`

**状态**：已接受 ｜ **驱动特征**：与既有测试一致、可追溯、最小改动 ｜ **决策日期**：2026-11-19

## 背景

Sprint 1 评审时提出一个悬而未决的问题：对**已软删除**的问题/回答做回答、编辑、采纳、投票、评论时，
实现返回 `422 QA-1008`，而《实验指导书》3.7 节的建议表里对应的场景写的是 `QA-1020`，Sprint 1 回顾
中也据此记了一条“需团队确认”的待办，但一直没有结论。

先把事实查清楚：

| 事实 | 依据 |
| :-- | :-- |
| `QA-1008` 出现在**起始代码自带**的 `docs/错误码.md` 中，v0.1.0 提交 `602bf5b` 即已存在 | `git show v0.1.0:docs/错误码.md` |
| 指导书 3.7 第一句：“`docs/错误码.md` **已给定的错误码必须严格使用**；未给定的场景，建议按下表补充” | 指导书 3.7 |
| `QA-1020` 在 3.7 表中的来源列标注为“**建议**”，正是“未给定场景”的补充建议 | 指导书 3.7 |
| 指导书另有 `QA-4001/4002/4003`（NotFound）用于“问题/回答/评论不存在或已删除” | 指导书 3.7 |
| 代码中 `QA-1008` 共 8 处抛出（`Question`、`Answer`、`CommentService`、`VoteService`），并有测试断言 | `grep -rn '"QA-1008"' backend/` |

也就是说：这不是“团队自创错误码偏离指导书”，而是**指导书要求优先使用已给定错误码**，`QA-1008`
属于“已给定”，`QA-1020` 属于“未给定场景的建议”。Sprint 1 回顾里的表述是误读。

## 决策

1. **保留 `QA-1008`** 作为“对已软删除内容执行写操作”的统一错误码，HTTP 状态 `422`，不做重编号。
2. 在 `docs/错误码.md` 中补一张**与指导书 3.7 的映射表**，明确“建议码 → 本团队采用码”，避免下次再问。
3. 区分两类语义，不再混用：
   - **资源不存在**（ID 查不到）→ `404` + `QA-4001/4002/4003`（NotFound）；
   - **资源存在但已软删除**（ID 查得到、`deleted_at` 非空）→ `422` + `QA-1008`（BusinessRule）。
4. 新增场景若 3.7 有“建议码”而 `docs/错误码.md` 未给定，**优先按建议码补充到 `docs/错误码.md`**，
   再实现；已给定的不因“指导书里有别的写法”而改动。

## 后果

- 正面：零代码改动、零测试改动，`CommentServiceTest` 等 8 处断言保持不变，不触碰学术诚信红线（9.3）；
  语义边界（404 不存在 vs 422 已删除）被写清楚，前端可按 `code` 精确提示。
- 负面：与指导书 3.7 的**字面**不一致，评审时可能被问；因此本 ADR 必须在评审会上主动出示，
  不要等老师发现。
- 约束：后续任何人不得为了“对齐指导书”而批量改错误码——那会连带修改既有断言。

## 被否决的替代方案

- **全量改为 `QA-1020`**：需要改 8 处实现 + 至少 1 个测试断言，违反“不修改已有断言”的约束，
  收益仅是字面一致。
- **改为返回 `404 NotFound`**：会把“已删除”与“不存在”合并，前端无法区分“链接失效”与“内容被删”，
  且 `404` 无法携带业务语义；指导书 3.7 把 `QA-1020` 归为 `BusinessRule` 也支持 422。
- **两个码都返回**（先 1020 再 1008）：语义重复，前端需处理两种分支，纯增复杂度。
