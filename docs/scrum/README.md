## 每份记录的五段结构

1. **Sprint Goal** —— 同时写进对应 Milestone 的描述；
2. **计划** —— 纳入的 PBI、故事点、负责人、承诺点数与容量；
3. **评审** —— 演示路径、逐条接受/退回、教师反馈；
4. **数据** —— 计划/完成点数、速度、燃尽图、PR 与 CI 指标、版本标签；
5. **回顾** —— 做得好的 / 待改进 / 改进行动（负责人 + 截止 + 跟踪 Issue）。

## 数据口径（避免争议）

| 指标 | 口径 |
| :-- | :-- |
| 完成点数 | 以**评审会接受**为准，不以“代码写完”为准 |
| PR 数 | 该 Sprint 窗口内 `merged_at` 落在此区间的 PR |
| 提交数 | 该窗口内作者日期落在区间的提交（`git log --date=short`） |
| CI 红灯 | 该窗口内创建的 workflow run 中 `conclusion=failure` 的数量 |
| 燃尽图 | 剩余点数按**工作日**统计；数据在 `burndown/sprint-N.csv` |

## 燃尽图

```bash
# 用真实数据重画某张图（需要 Python 3 + Pillow）
python scripts/po/burndown.py docs/scrum/burndown/sprint-1.csv
```

**由 SM 站会后补当日剩余点数**，补完运行上面的命令即可出图。
