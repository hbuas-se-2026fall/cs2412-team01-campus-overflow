## 部署

前置条件：Docker ≥ 20.10 且 compose v2 可用、≥ 2 核 4 GB、对外端口空闲。

```bash
git clone https://github.com/hbuas-se-2026fall/cs2412-team01-campus-overflow.git
cd cs2412-team01-campus-overflow

cp deploy/.env.example deploy/.env
# 必填三项：
#   MYSQL_ROOT_PASSWORD / DB_PASSWORD   ← 自定义强密码
#   CO_FIELD_KEY                        ← openssl rand -base64 32
# 纯 HTTP 演示必须 COOKIE_SECURE=false；走 HTTPS 时保持 true

bash deploy/deploy.sh          # 构建 + 启动 + 等后端 healthy
```

部署成功后：

- 前端：`http://<服务器IP>:<WEB_PORT>`（默认 80）
- 接口文档：`http://<服务器IP>:<WEB_PORT>/swagger-ui.html`
- 健康检查：`http://<服务器IP>:<WEB_PORT>/actuator/health`

**首次构建约 15 分钟**（拉 6 个基础镜像 + 容器内 Maven 构建 + `npm install`），这是 PC 上的实测值，
不是文档里的理想值；后续增量构建约 1~3 分钟。

开启监控（可选）：

```bash
cd deploy && docker compose -f docker-compose.prod.yml --env-file .env --profile observability up -d
# Prometheus 9090 / Grafana 3000 只绑 127.0.0.1，本机访问需 SSH 隧道：
#   ssh -L 9090:127.0.0.1:9090 -L 3000:127.0.0.1:3000 <user>@<服务器IP>
```

发布前请在干净环境按 [一键部署验收清单](../reports/deploy-acceptance.md) 逐条核对（8 条断言 + 回滚演练）。

## 升级与回滚

- **升级**：`git pull` 后重跑 `bash deploy/deploy.sh`。Flyway 迁移随容器启动自动执行，无需手工建表。
- **回滚**：`bash deploy/deploy.sh rollback` 回到上一次成功部署的镜像（`campus-overflow/backend:rollback`），数据卷不动。
- **迁移不可逆**：本版没有破坏性 schema 变更；若后续版本有，会在对应 Release Notes 里单独标注。

## 已知限制

照实写，评审时不必回避：

- **未配置 required status check**：`e2e` 变红也能合并，靠组内约定「不绿不请求评审」；
- **前端只有 7 个页面**：无管理页、无个人资料页（PB-41 / PB-47 未做）；
- **通知红点是 30 秒轮询**，不是 SSE 推送（PB-43 未做）；
- **没有压测**：缓存命中率与 P95 延迟没有数据支撑（PB-45 未做）；
- **浏览器端验证不完整**：部署冒烟用 `curl`，它比浏览器宽松；`COOKIE_SECURE` 配错时，
  浏览器表现为「登录成功但立刻 401」，而 `curl` 仍显示 200；
- **HTTPS 未覆盖**：`deploy/nginx.conf` 只监听 80，证书与外层反代需要部署方自行处理。
