## 质量与验证

### 端到端测试进入 CI（#119）

新增独立的 `e2e` job，与 `backend`、`frontend` 并行，总时长仍由 `backend` 决定。

| 指标 | 实测 |
| :-- | :-- |
| `CampusOverflowFlowIT` | 4/4 通过 |
| 用例耗时 | 29.60 s（run #151）/ 38.21 s（run #152） |
| 容器 | `mysql:8.0.39`、`redis:7-alpine`、`ryuk:0.12.0` 正常起停 |
| job 总耗时 | 约 1.6 min，含拉取镜像 |

`backend` job 仍然带 `-DskipITs`，覆盖率门禁（领域层 ≥ 0.75）不受影响。

### 部署冒烟（#124）

`deploy/` 的生产编排（MySQL + Redis + backend + nginx）此前从未真正跑过。新增的手动工作流在
GitHub runner 上跑一遍 `docker-compose.prod.yml`，验证到「注册 → 登录 → `/auth/me` 200」为止。

首次运行暴露了一个真实缺陷：后端镜像 `COPY` 的 jar 名与 pom 的 `<finalName>` 不一致，
容器报 `Unable to access jarfile app.jar`。已在 #124 中修复。

### CI 效率（#120 / #131）

- `changes` job 判定变更范围：纯文档 PR 不再安装 JDK、不再跑 9 个模块的 `verify`；
  判定失败时**兜底全量运行**，主干 push 无条件全量，保留 9.1 要求的主干绿色证据。
- 前端改用 `npm ci`（依赖 lockfile），构建可复现。
- 后端 job 上传 JaCoCo 站点与 surefire 报告为 artifact（保留 30 天），评审材料可直接引用。

## 部署

```bash
cp deploy/.env.example deploy/.env    # 填 MYSQL_ROOT_PASSWORD / DB_PASSWORD / CO_FIELD_KEY
# 纯 HTTP 演示时 COOKIE_SECURE=false；走 HTTPS 时保持 true
bash deploy/deploy.sh
```

`deploy/deploy.sh` 会做前置检查、构建镜像、等待后端 healthy，失败时输出最近 50 行日志并保留镜像供回滚。
