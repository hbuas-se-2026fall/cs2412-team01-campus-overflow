# 业务错误码

所有错误响应遵循 RFC 9457 Problem Details，并扩展 `code` 字段：

```json
{ "type": "about:blank", "title": "Unprocessable Entity", "status": 422,
  "detail": "不能给自己的内容投票", "code": "QA-1015" }
```

## 分段约定

| 前缀 | 上下文 | 段位含义 |
| --- | --- | --- |
| `ID-` | Identity | `1xxx` 业务规则 / `2xxx` 冲突 / `3xxx` 权限 / `4xxx` 未找到 |
| `QA-` | Q&A | 同上 |
| `REP-` | Reputation | 同上 |
| `DIS-` | Discovery | 同上 |
| `AUTH-` | 认证与 CSRF | 401 / 403 / 429 |
| `SYS-` | 平台级 | 参数校验、并发冲突、未知异常 |

## HTTP 状态映射

| 领域异常 | 状态码 | 典型场景 |
| --- | --- | --- |
| `BusinessRuleException` | 422 | 违反业务规则（自投票、悬赏积分超限） |
| `ConflictException` | 409 | 状态冲突（重复采纳、悬赏已结束） |
| `ForbiddenException` | 403 | 权限不足（非提问者采纳、越权查看流水） |
| `NotFoundException` | 404 | 资源**不存在**（ID 查不到），或**读操作**命中已软删除内容（读模型按不存在处理，见下方映射表） |
| 乐观锁失败 | 409 `SYS-409-CONCURRENT` | 并发编辑同一内容 |
| 唯一约束冲突 | 409 `SYS-409-DUPLICATE` | 重复提交（如并发投票） |

## Q&A 上下文错误码明细（S2）

领域层实际抛出的全部错误码与触发条件。应用层与前端据此做分支处理，
**不要靠匹配错误消息文本判断**——消息可能随文案调整而变化，`code` 才是契约。

### 1xxx 业务规则（→ 422 `BusinessRuleException`）

| 错误码 | 触发条件 | 抛出位置 |
| --- | --- | --- |
| `QA-1001` | 标题不在 10–150 字符（按 Unicode 码点计） | `Title` |
| `QA-1002` | 问题正文不在 20–30000 字符；回答正文不在 10–30000 字符；评论正文不在 1–600 字符 | `MarkdownBody`、`Comment.post` |
| `QA-1004` | 标签为空，或不匹配 `^[\p{L}\p{N}][\p{L}\p{N}#+.\-_]{0,29}$` | `TagName` |
| `QA-1005` | 去重后标签数不在 1–5 个 | `Tags` |
| `QA-1006` | 投票值不是 +1 或 -1 | `Vote.cast`、`Vote.change` |
| `QA-1007` | 回复二级评论（只支持一层） | `Comment.post` |
| `QA-1012` | 回复与父评论的 `targetType`/`targetId` 不一致（挂错内容） | `Comment.post` |
| `QA-1008` | 对已软删除的问题/回答执行编辑、采纳、回答、删除 | `Question`、`Answer` |
| `QA-1009` | 采纳的回答 `questionId` 与当前问题不符 | `Question.accept` |
| `QA-1010` | 提问者删除 `answerCount > 0` 的问题（课程管理者不受限） | `Question.softDelete` |
| `QA-1011` | 回答者删除已被采纳的回答（防「先骗采纳再删除」，课程管理者不受限） | `Answer.softDelete` |
| `QA-1015` | 投票者与内容作者是同一人 | `Vote.cast` |

### 2xxx 状态冲突（→ 409 `ConflictException`）

| 错误码 | 触发条件 | 抛出位置 |
| --- | --- | --- |
| `QA-2002` | 问题已有 `acceptedAnswerId`，再次采纳 | `Question.accept` |
| `QA-2003` | 回答已有 `endorsedBy`，再次认证 | `Answer.endorse` |

### 3xxx 权限不足（→ 403 `ForbiddenException`）

| 错误码 | 触发条件 | 抛出位置 |
| --- | --- | --- |
| `QA-3001` | 采纳者既非提问者本人，也非课程管理者 | `Question.accept` |
| `QA-3002` | 编辑者既非内容作者，也非课程管理者 | `Question.edit`、`Answer.edit` |
| `QA-3003` | 删除者既非内容作者，也非课程管理者 | `Question.softDelete`、`Answer.softDelete` |
| `QA-3004` | 认证者不是课程管理者（回答者本人亦无权认证自己的回答） | `Answer.endorse` |

### 4xxx 未找到（→ 404 `NotFoundException`）

| 错误码 | 含义 | 抛出位置（v0.3.0） |
| --- | --- | --- |
| `QA-4001` | 问题不存在（含读模型按 `deleted_at IS NULL` 过滤后的“已删除”） | `AnswerCommandService:122`、`CommentService:70`、`QuestionCommandService:114`、`VoteService:94`、`QuestionQueryService:67`、`BountyService:62`※ |
| `QA-4002` | 回答不存在 | `AnswerCommandService:126`、`CommentService:59`、`VoteService:102` |
| `QA-4003` | 课程不存在 | `QuestionCommandService:127` |
| `QA-4004` | 被回复的评论不存在 | `CommentService:43` |

> ※ `BountyService` 属于 Reputation 上下文，却抛了 `QA-` 前缀的码，与“前缀 = 上下文”的分段约定不符；
> 改码要连带改测试，单独开 PR 处理，记录见 [ADR-010](adr/010-已删除内容的错误码.md) 的「已知不一致」。

### 关于「课程管理者」

3xxx 段的判据统一为 **「内容作者本人 `||` `actorManagesCourse`」**。

`actorManagesCourse` 是一个由**应用层**计算后传入领域方法的布尔值，表示
「当前操作者是否管理该问题所属的课程」。领域层不自行调用
`Actor.isTeacherOrAdmin()`——全局角色（TEACHER/ADMIN）与课程内角色
（某门课的教师/助教）是两件事，后者属于 Identity 上下文的课程成员关系，
跨上下文只能经 `*-api` 查询。

> 实现应用层时请注意：一位 `Role.TEACHER` 的用户若不教这门课，
> `actorManagesCourse` 应为 `false`，不能一律放行。

### 正文长度取值说明

| 场景 | 范围 | 依据 |
| --- | --- | --- |
| 问题正文 | 20–30000 | 上限见 `QuestionController` `@Size(max = 30000)`；下限见 `AskPage.tsx`「至少 20 字」提示与 `QuestionTest` 的 22 字边界用例 |
| 回答正文 | 10–30000 | 上限见 `AnswerController` `@Size(max = 30000)`；**下限 10 为实现时的暂定值**，领域测试中最短用例为 13 字，无下界断言 |
| 评论正文 | 1–600 | 上限见 `CommentController` `@Size(max = 600)` |

> ⚠️ 回答正文下限 10 字属于产品决策，尚未经 PO 确认。若需调整，
> 改 `MarkdownBody.MIN_ANSWER` 一处即可。

## 与《指导书》3.7 建议码的映射（ADR-010）

指导书 3.7 的原则是「`docs/错误码.md` **已给定**的错误码必须严格使用；未给定的场景建议按下表补充」。
本表记录团队的实际取值，**已给定项一律不改**，未给定项按建议码补充后写回本文件。

| 场景 | 指导书 3.7 | 本团队取值 | 说明 |
| --- | --- | --- | --- |
| **写操作**命中已软删除的问题/回答（回答、编辑、采纳、投票、评论） | `QA-1020`（建议） | `QA-1008`（团队在 S1 按分段约定自行编号并写回文档，422） | 起始代码只有 1001/1002/1005/1015；1008 由 `468668c` 引入；改号需改 7 处实现与 1 处断言，放弃（见 [ADR-010](adr/010-已删除内容的错误码.md)） |
| **读操作**命中已软删除的问题/回答（详情、列表） | — | `QA-4001/4002`（404） | 读模型 SQL 带 `deleted_at IS NULL`，已删除内容查不到，按不存在处理 |
| 问题/回答/评论**不存在**（ID 查不到） | `QA-4001/4002/4003` | 同（404） | 与「已删除」区分：写路径已删除是 422，读路径与真不存在同为 404 |
| 评论正文长度不合法（1–600 字） | `QA-1003`（建议） | `QA-1002`（已给定，422） | 已给定，不改；`QA-1003` 未采用（`Comment.java:36` 用 `QA-1002`） |
| 评论回复层级 / 父评论目标不一致 | `QA-1016/1017`（建议） | `QA-1007/1012` | 已给定，不改 |
| 投票值非法 | `QA-1014`（建议） | `QA-1006` | 已给定，不改 |
| 回答不属于该问题 | `QA-1010`（建议） | `QA-1009` | 已给定，不改 |

> 评审时的标准回答：「已给定码优先于建议码」。语义边界按路径区分：
> **写操作**命中已删除内容 → `422 QA-1008`；**读操作**命中已删除内容或 ID 本来就不存在 → `404 QA-4001/4002`。
